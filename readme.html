Architecture

How it works

The whole thing is a local pipeline. Nothing touches the internet at runtime.

💬
You type a plain English question "Show 10 customer names and account numbers"
⚡
Angular sends it to FastAPI JWT-authenticated request hits the backend on port 8000
🗄️
FastAPI pulls live schema + your saved metadata Column names, table names, and your plain-English descriptions get assembled into the prompt
🤖
LM Studio generates the SQL Local LLM on port 1234 — Qwen2.5-Coder reads the schema and writes the query
🔒
FastAPI validates and executes Only SELECT gets through. DDL and DML are rejected before they touch the database.
📊
Results rendered + exportable Table in the browser, one click to Excel

Setup

Getting started

Before anything else: Make sure SQL Server is running with Mixed Mode Auth enabled, ODBC Driver 18 is installed, and LM Studio has a model loaded with Local Server switched on.

1. Clone the repo

git clone https://github.com/Aumaswar/TablyAI.git
cd tablyai

2. Backend

cd ai-backend
pip install -r requirements.txt

3. Frontend

cd ai-frontend
npm install

4. Database objects

Two tables need to exist in your application database before the backend will start:

CREATE TABLE app_users (
    id            INT IDENTITY PRIMARY KEY,
    username      NVARCHAR(100) NOT NULL UNIQUE,
    password_hash NVARCHAR(255) NOT NULL,
    role          NVARCHAR(50)  NOT NULL
);

CREATE TABLE metadata_definitions (
    id               INT IDENTITY PRIMARY KEY,
    table_name       NVARCHAR(200) NOT NULL,
    column_name      NVARCHAR(200) NOT NULL,
    business_meaning NVARCHAR(500)
);

5. Start everything — in this order

# 1. SQL Server should already be running

# 2. LM Studio → load model → start Local Server
#    Running at http://127.0.0.1:1234/v1

# 3. Backend
cd ai-backend
uvicorn main_langchain:app --reload
# → http://localhost:8000

# 4. Frontend (new terminal)
cd ai-frontend
ng serve
# → http://localhost:4200
The Smart Part

The metadata system

This is what makes it actually work on real production databases — not just demo ones.

Real column names are rarely self-explanatory. CustAcctNbr, PrdRevDt, BusnEntID — the model has no idea what these mean without context. The metadata system lets you attach plain English descriptions to any column directly inside the app. Those descriptions get injected into the prompt at query time.

Pro tip: The more columns you describe, the better the joins get. Focus first on foreign keys and any columns with abbreviated or cryptic names.

Security

Built-in protections

This isn't a toy pointed at a throwaway database. These controls are on by default.

🔑
JWT on every endpointNo token, no access. Tokens are role-encoded and validated on every request.
👥
Role-based accessAdmin and viewer roles enforced at the API level, not just the UI.
🚫
Read-only enforcementOnly SELECT statements get through. Everything else is rejected before execution.
🛡️
DDL/DML blockedINSERT, UPDATE, DELETE, DROP, ALTER — all rejected at the validation layer.
✅
SQL validationEvery generated query is parsed and checked before it ever touches the database.
🏠
100% localNo data leaves your machine. The LLM, the API, and the database all run on localhost.
